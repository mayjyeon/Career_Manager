# Career_Manager

학생 진로상담 관리 웹 애플리케이션입니다.

기존 C#(WPF + EF Core/SQLite) 데스크톱 프로그램인
[`simsy0924/CareerManagerProgram`](https://github.com/simsy0924/CareerManagerProgram)을
JavaScript 웹사이트로 옮긴 것입니다.

Google 계정으로 로그인하고, 학생·상담 데이터는 Firebase(Firestore)에 저장합니다.
`main` 브랜치에 푸시하면 GitHub Actions 가 GitHub Pages 로 자동 배포합니다.

## 화면 구성

로그인한 계정에 따라 **선생님 화면**과 **학생 화면**이 다르게 열립니다.

### 선생님 화면

| 화면 | 설명 |
| --- | --- |
| 대시보드 | 관리 중인 학생 수, 누적 상담 수, 최근 상담 기록 8건 |
| 학생 관리 | 학생 검색·추가·수정·비활성화·일괄 삭제, 명렬표 엑셀 업로드, 학생 계정 연결 확인 |
| 상담일지 | 학생 검색, 상담 기록 조회·검색·추가·수정·삭제, 주인 없는 기록 정리, 진로상담일지·진로상담총괄표 내보내기 |
| 공지사항 | 공지 작성·수정·삭제, 학년·반별 공개 |
| 과제 | 과제 출제와 학생별 제출물 확인 |
| 포트폴리오 | 학생 검색, 엑셀 일괄 등록·직접 등록, 학생들이 올린 포트폴리오 열람 |
| 세특 및 활동 | 엑셀 업로드·직접 작성·엑셀 내보내기, 바이트 수 자동 계산 |
| 통계 | 월별 상담 추이, 상담 구분 비율, 학년·반별 현황 |
| 휴지통 | 종류·내용 검색, 지운 자료 되살리기·완전 삭제 |

학생 관리·상담일지·포트폴리오·세특·휴지통은 **같은 모양의 검색 막대**를 씁니다
(`assets/js/views/search-bar.js`). 검색 조건은 화면을 옮겨 다녀도 유지됩니다.

### 학생 화면

| 화면 | 설명 |
| --- | --- |
| 홈 | 내야 할 과제, 새 공지, 내 포트폴리오 수, 회원 탈퇴 |
| 공지사항 | 내 학년·반이 대상인 공지 열람 |
| 과제 | 과제 확인, 제출·수정·제출 취소 |
| 포트폴리오 | 내 진로 활동 기록 추가·수정·삭제 |
| 휴지통 | 내가 지운 자료 되살리기 |

반응형 레이아웃과 다크 모드도 지원합니다.

## 지우기와 휴지통

지운 자료는 곧바로 사라지지 않고 **휴지통에서 30일 동안** 기다립니다.
그동안은 언제든 되살릴 수 있고, 기간이 지나면 자동으로 정리됩니다.

- **학생 삭제** — 학생 관리에서 여러 명을 골라 한 번에 지웁니다(자퇴·졸업 등).
  소속·상담 기록·선생님이 등록한 포트폴리오·세특도 함께 들어가며, 되살리면 같이 돌아옵니다.
  완전 삭제할 때는 그 학생의 자료를 **하나도 남기지 않고** 지웁니다.
  전에 따로 지워 두었던 상담 기록까지 함께 없애야 주인 없는 기록이 남지 않습니다.
  잠깐 목록에서만 빼려면 삭제 대신 **비활성화**를 쓰세요.
  비활성화한 학생도 상담일지에서는 골라 볼 수 있어 기록을 열어 보거나 지울 수 있습니다.
- **회원 탈퇴** — 학생이 홈 화면 아래에서 직접 탈퇴합니다.
  내 정보·제출물·포트폴리오를 **휴지통을 거치지 않고 바로** 지우고 로그아웃합니다.
  구글 계정 자체는 그대로 남아, 다시 로그인하면 새로 시작합니다.

> 서버가 따로 없는 정적 사이트라 ‘30일 뒤 자동 삭제’ 는
> 앱을 열 때 지난 항목을 찾아 지우는 방식으로 동작합니다.
> 한동안 아무도 접속하지 않으면 그만큼 늦게 정리됩니다.

### 주인 없는 상담 기록

학생은 사라졌는데 상담 기록만 남는 경우가 있습니다.
옛 형식에서 옮겨 온 자료, 또는 학생 문서만 따로 지워진 경우입니다.
이런 기록은 학생 목록에 없어 화면에서 고를 수 없으면서 통계에는 계속 잡혀
상담 건수·상담 시간·상담한 학생 수를 부풀립니다.

- **통계** 는 주인 없는 기록을 빼고 셉니다. 몇 건을 뺐는지 화면 위에 알려 줍니다.
- **상담일지** 아래쪽에 ‘주인 없는 상담 기록’ 카드가 뜹니다.
  날짜·회기·주제·내용을 확인하고 골라서, 또는 한 번에 모두 지울 수 있습니다.
  휴지통을 거치므로 잘못 지워도 30일 안에는 되돌릴 수 있습니다.

## 임시 저장

공지·과제·제출물·포트폴리오처럼 글이 긴 화면은 **입력하는 동안 이 브라우저에 자동 보관**합니다.
실수로 창을 닫아도 다시 열면 “쓰다 만 내용이 있습니다” 안내가 뜨고, 원할 때만 불러옵니다.
저장을 마치면 지워지며, 보관한 내용은 서버로 보내지 않아 다른 기기에서는 보이지 않습니다.

## 사용량은 Firebase 콘솔에서

Firestore 를 얼마나 읽고 쓰는지는 앱이 아니라
[Firebase 콘솔의 사용량 및 청구액](https://console.firebase.google.com/) 페이지에서 봅니다.

앱 안에 넣으려고 Google Cloud Monitoring 을 붙여 봤지만,
시계열을 읽는 `timeSeries.list` 메서드가 **결제 계정을 연결해야만** 동작합니다.

```
This Cloud Monitoring API method requires billing to be enabled.
```

API 자체는 기본으로 켜져 있고 인증도 통과하지만 이 메서드만 막힙니다.
프로젝트 전체 사용량을 무료로 주는 다른 경로는 찾지 못했습니다.
(Cloud Billing API 도 같은 제약, Firebase Management API 와 Firestore Admin API 에는
사용량 지표가 없고, 콘솔 내부 엔드포인트는 세션 인증이라 정적 사이트에서 부를 수 없습니다.)

앱이 스스로 세는 방법도 있지만 **접속한 브라우저에서 일어난 양만** 잡힙니다.
학생 수십 명이 만드는 읽기는 빠져서, 무료 한도에 가까운지 보려고 여는 화면이
실제보다 훨씬 적게 나오면 오히려 오해를 부릅니다. 그래서 넣지 않았습니다.

## 선생님과 학생 구분

`assets/js/roles.js` 의 `TEACHER_EMAIL` 에 적힌 계정으로 로그인하면 선생님,
그 밖의 구글 계정은 모두 학생으로 봅니다.

```js
export const TEACHER_EMAIL = "mayjyeon52@gmail.com";
```

> 이 값을 바꿀 때는 `firestore.rules` 안의 같은 주소도 함께 고쳐야 합니다.
> 화면만 바꾸면 데이터 접근 권한은 그대로 남습니다.

학생은 처음 로그인할 때 **학년·반·번호와 이름**을 입력합니다.
이 값으로 자기에게 온 공지와 과제를 받아 봅니다.

선생님은 **학생 관리** 화면 아래쪽 ‘학생 계정 연결’ 표에서
학생이 적은 값이 명렬표와 맞는지 확인할 수 있습니다.
학생이 직접 적는 값이라 틀릴 수 있어, `이름 다름`·`명렬표에 없음` 으로 표시된 학생은
따로 확인해 주세요.

## 파일 첨부는 링크로

공지·과제·제출물·포트폴리오에는 **파일을 직접 올리지 않고 주소를 붙입니다.**
구글 드라이브·유튜브 등에 올린 뒤 주소를 넣으면 됩니다.

- 유튜브 영상과 이미지 주소는 화면에서 바로 펼쳐 보입니다.
- `제목 | 주소` 로 적으면 그 제목으로 보입니다.
- 드라이브 파일은 **링크가 있는 모든 사용자**로 공유해 두어야 학생이 열 수 있습니다.

> 파일을 앱에 직접 올리려면 Cloud Storage 가 필요한데,
> 2026년 2월부터 결제 계정(Blaze 요금제)을 연결해야 쓸 수 있습니다.
> Firestore 에 파일을 넣는 방법도 무료 용량이 1GB 뿐이라 금방 찹니다.
> 그래서 비용이 들지 않는 링크 첨부 방식을 씁니다.

## 명렬표 엑셀 업로드

**학생 관리 → 명렬표 업로드** 에서 학급 명렬표 파일을 올리면 학생을 한 번에 등록합니다.

학교에서 쓰는 아래 형태의 **교차표**를 그대로 읽습니다.

```
              2026학년도 1학년 학급명렬표
 ┌──────┬───────────────────────┬──────┬───────────────────────┐
 │ 번호 │           남          │ 번호 │           여          │
 │      │ 1반 │ 2반 │ 3반 │ …   │      │ 6반 │ 7반 │ 8반 │ …   │
 ├──────┼─────┼─────┼─────┼─────┼──────┼─────┼─────┼─────┼─────┤
 │  1   │홍길동│                 │  1   │김영희│                 │
```

- **학년도·학년** 은 맨 위 제목에서 읽습니다.
- **반** 은 `○반` 제목이 있는 열에서, **번호** 는 왼쪽 `번호` 열에서 읽습니다.
- 병합된 `남`/`여` 구역으로 성별까지 함께 저장합니다.
- `학년도·학년·반·번호·이름` 열이 있는 **목록형** 명렬표도 읽을 수 있습니다.

읽어 들인 내용은 저장하기 전에 미리보기로 보여 줍니다.
이미 같은 학년도·학년·반·번호에 학생이 있으면 **중복**으로 표시되고,
줄마다 *건너뛰기* 또는 *덮어쓰기* 를 고를 수 있습니다(기본값은 건너뛰기).

| 형식 | 지원 |
| --- | --- |
| `.xlsx` · `.xlsm` | ✅ |
| `.csv` (UTF-8 · EUC-KR) | ✅ |
| 나이스에서 받은 HTML 표 형태의 `.xls` | ✅ |
| 예전 엑셀 이진 형식 `.xls` | ❌ 엑셀에서 `.xlsx` 로 저장한 뒤 올려주세요 |

## 포트폴리오 엑셀 업로드

**포트폴리오 → 엑셀 업로드** 에서 선생님이 정리해 둔 표를 올리면
학생별 포트폴리오로 한 번에 채웁니다.
읽는 칸은 **`현재학번`** 과 **`글내용(통합)`** 두 개뿐이고 **나머지 칸은 모두 무시**합니다.

```
 ┌──────┬──────────┬────────────────────┬──────┐
 │ 이름 │ 현재학번 │    글내용(통합)     │ 비고 │   ← 이름·비고는 읽지 않습니다
 ├──────┼──────────┼────────────────────┼──────┤
 │ 김하늘│  30112   │ 의료 계열 진로 탐색…│      │
 │ 박바다│  10203   │ 동아리 활동 기록    │      │
```

- 열 순서는 상관없습니다. 머리글 이름으로 찾으므로 `현재 학번`, `글 내용 (통합)`
  처럼 띄어쓰기가 달라도 읽습니다.
- **학번은 5자리** 입니다. `학년 1 + 반 2 + 번호 2` 로, `10203` 이면 1학년 2반 3번입니다.
- 파일 안에서 학번이 뒤죽박죽이어도 **학년·반·번호 순으로 정렬**해서 보여 줍니다.
- 같은 학번이 여러 줄에 나오면 그 학생에게 **여러 건**으로 붙습니다.
- 엑셀에 제목 칸이 없으므로 **올릴 때 제목을 한 번 적으면** 그 파일의 모든 글에 같은 제목을 씁니다.

미리보기에서 **학년도** 를 고르면 그 학년도 명렬표에서 학번에 해당하는 학생을 찾습니다.

| 상태 | 뜻 |
| --- | --- |
| 등록 | 명렬표에서 학생을 찾았습니다. 이 줄만 저장됩니다. |
| 학생 없음 | 그 학년도·학년·반·번호에 등록된 학생이 없습니다. 명렬표를 먼저 올려주세요. |
| 확인 필요 | 학번을 5자리로 읽지 못했거나 글내용이 비어 있습니다. |

올린 자료는 **선생님만 봅니다.** 학생 화면에는 나오지 않습니다.
학생 한 명씩 적어 넣을 때는 **+ 직접 등록** 을 쓰고, 등록한 뒤에도 수정·삭제할 수 있습니다.

## 세특 및 활동

세부능력 및 특기사항을 엑셀로 올리거나 직접 적고, 필요할 때 다시 엑셀로 내보냅니다.
**선생님만 보는 자료**로 학생 화면에는 나오지 않습니다.

### 올리기

기본 칸은 **학번 · 이름 · 세특 내용 · 바이트 수** 네 개입니다.

```
 ┌──────┬──────┬─────────────────────┬──────────┬──────┬──────┐
 │ 학번 │ 이름 │      세특 내용       │ 바이트 수 │ 과목 │ 학기 │
 ├──────┼──────┼─────────────────────┼──────────┼──────┼──────┤
 │10203 │박바다│ 동아리에서 심폐소생술…│   1,024  │ 보건 │ 1학기│
                                        └ 다시 세므로     └ 덧붙인 칸
                                          읽지 않습니다     (그대로 보관)
```

- 열 순서는 상관없습니다. 머리글 이름으로 찾으므로 `현재학번`, `성명`,
  `세부능력 및 특기사항` 처럼 달리 적어도 읽습니다.
- **학번은 5자리**(학년 1 + 반 2 + 번호 2)이고, 파일 안에서 뒤죽박죽이어도
  학년·반·번호 순으로 정렬해 보여 줍니다.
- **모르는 칸(과목·학기·비고 등)은 이름 그대로 보관**했다가 내보낼 때 함께 내보냅니다.
  몇 개를 찾았는지 미리보기에서 알려 줍니다.
- 시트가 여러 개면 모두 읽고, 어느 시트에서 왔는지 잃지 않도록 `시트` 칸을 덧붙입니다.

### 바이트 수

**저장하지 않고 내용에서 그때그때 셉니다.** 내용을 고쳐도 값이 어긋나지 않습니다.
엑셀에 적혀 온 바이트 수는 읽지 않고 버립니다.

기준은 나이스와 같습니다.

| 글자 | 바이트 |
| --- | ---: |
| 한글 | 3 |
| 영문·숫자·기호·공백·줄바꿈 | 1 |

직접 작성하는 창에서는 적는 동안 바이트 수가 따라 바뀝니다.

### 내보내기

**학번 · 이름 · 세특 내용 · 바이트 수** 뒤에 덧붙였던 칸이 그대로 따라 나갑니다.
학번 순으로 정렬하고 바이트 수는 다시 세어 넣습니다.
검색 조건이 걸려 있으면 *검색 결과만* 과 *전체* 중에서 고를 수 있습니다.

엑셀 파일(`.xlsx`)은 `assets/js/xlsx.js` 가 외부 라이브러리 없이 만듭니다
(`.xlsx` 는 XML 몇 개를 담은 ZIP 이라 `zip.js` 로 묶으면 됩니다).
머리글 고정·자동 필터·줄바꿈·열 너비가 들어 있어 열자마자 읽을 만하고,
엑셀·구글 스프레드시트·LibreOffice 에서 모두 열립니다.

## 한글 문서 내보내기

상담 기록은 학교에서 쓰는 두 가지 서식으로 내려받을 수 있습니다.
파일 형식은 둘 다 한글의 공개 표준인 **`.hwpx`** 입니다.
한컴오피스 한글 2010 이상과 한컴독스에서 바로 열리고,
한글에서 *다른 이름으로 저장* 하면 `.hwp` 로 바꿀 수 있습니다.
(비공개 이진 형식인 `.hwp` 는 브라우저에서 직접 만들 수 없습니다.)

### 진로상담일지

상담 한 건이 한 쪽인 A4 서식입니다. 그대로 인쇄해서 철하면 됩니다.

- **상담일지 → 상담일지 내보내기** 는 기간(과 학생)을 정해 여러 건을 한 문서로 묶습니다.
- 상담 기록 카드의 **📄 일지** 는 그 한 건만 바로 내려받습니다.
- 용지·칸 너비·줄 높이·글자 크기는 원본 한글 파일에서 읽은 값을 그대로 씁니다.
  (`assets/js/counseling-docs.js`)
- 입력 칸이 곧 서식의 칸입니다.

  | 서식의 칸 | 입력 |
  | --- | --- |
  | 내담자 정보 | 선택한 학생의 학년·반·번호·이름 |
  | 상담일시 | 상담 날짜와 시간대 — `수업 중(교시)` 이면 교시·교과명을 함께 적습니다 |
  | 상담 주제 | `진로 / 진학 / 선택교과 / 학업 / 기타` 중 여러 개 (기타는 사유 필수) |
  | 내담자가 진술한 문제와 상황 | 학생이 이야기한 내용 |
  | 상담자 소견 및 개입 | 선생님의 소견과 조치 |

- 제목 줄의 학교명과 담당자·내선번호는 내보내기 화면에서 고칠 수 있고,
  한 번 고치면 이 브라우저에 기억됩니다.
- 원본 서식의 체크 표시(윙딩스 ✔)는 글꼴이 없는 곳에서 깨지므로
  어느 한글 글꼴에나 있는 `√` 를 씁니다.
- `점심시간 / 하교 후` 는 원본대로 둘 다 인쇄하고 고른 쪽만 진하게 표시합니다.

### 진로상담총괄표

**상담일지 → 총괄표 내보내기** 에서 기간을 정하면
그 기간의 상담 기록을 학교 결재 서식(진로상담총괄표)에 채워 한글 문서로 내려받습니다.

- **학번** 은 학년·반·번호로 만든 5자리 숫자입니다. (1학년 3반 5번 → `10305`)
- **상담 구분** 은 서식과 같은 `진로 / 진학 / 기타` 3종이라,
  상담일지에서 고른 `선택교과` 와 `학업` 은 여기서 **기타** 로 셉니다.
- **상담시간** 합계와 하단 누계표(A·C·주당시수)를 자동으로 계산합니다.
  내보낼 때 **학기 적용 주 수(B)** 와 **주당 수업시수(D)** 를 입력받습니다.
- 이 서식은 **50분을 한 시간(차시)** 으로 셉니다.
  (`assets/js/counseling-docs.js` 의 `MINUTES_PER_HOUR`)

문서 만들기는 모두 브라우저 안에서 이뤄져 상담 내용이 외부로 나가지 않습니다.
외부 라이브러리 없이 브라우저에 내장된 압축 기능(`CompressionStream`)만 씁니다.

## 데이터 저장

데이터는 **Firestore** 에 저장하며, 두 종류로 나뉩니다.

학생 명부와 상담 기록은 선생님 계정 안에만 있고 본인만 읽고 씁니다.

```
users/{uid}/classes/{학년도-학년-반}      한 반 (그 반 학생 전원이 배열로)
users/{uid}/sessions/{id}                상담 기록 (날짜·회기·주제·시간대·소요시간·내용)
users/{uid}/portfolios/{학년도-학년-반}    선생님이 등록한 포트폴리오 (한 반 분량이 배열로)
users/{uid}/achievements/{학년도-학년-반}  세특 및 활동 (한 반 분량이 배열로)
```

포트폴리오는 두 갈래입니다.
학생이 스스로 올린 것은 아래 공용 컬렉션(`portfolios/{id}`)에 있고,
**선생님이 엑셀로 올리거나 직접 적어 넣은 것**은 선생님 계정 안에 있어 학생에게는 보이지 않습니다.
학생 명부와 같은 반 문서 구조라 한 반 30명 분량이 문서 하나로 나갑니다.

### 학생은 왜 한 명씩 문서가 아닌가

Firestore 는 **리스너로 배달된 문서 1개당 읽기 1건**을 매깁니다.
그게 방금 내가 쓴 문서라도 예외가 없습니다.

처음에는 학생 한 명이 문서 하나(`students`)였고 소속이 또 다른 문서(`schoolYears`)였습니다.
그래서 900명짜리 명렬표를 한 번 올리면 이렇게 됐습니다.

| | 낱개 문서 | 반 단위 묶음 |
| --- | ---: | ---: |
| 명렬표 900명 업로드 — 쓰기 | 1,800건 | **30건** |
| 명렬표 900명 업로드 — 되돌아온 읽기 | 1,800건 | **30건** |
| 선생님 로그인 — 읽기 | 1,800건 | **30건** |

하루 무료 한도가 쓰기 2만·읽기 5만이라, 업로드 한 번에 그날 쓰기의 9% 를 썼습니다.

지금은 한 반이 문서 하나이고 그 안에 학생이 배열로 들어 있습니다.
학생 한 명이 약 120바이트라 30명이 모여도 5KB 남짓으로, 문서 한도 1MiB 의 0.5% 입니다.
학생 한 명만 고쳐도 쓰기는 여전히 1건이고, 반을 옮길 때만 2건(뺀 반·넣은 반)입니다.

**되지 않는 방법:** "업로드하는 동안만 리스너를 떼자"는 효과가 없습니다.
다시 붙일 때 SDK 가 resume token 이후의 변경분을 요청하는데, 그 변경분이 방금 쓴 문서 전부입니다.
지금 낼지 이따 낼지가 바뀔 뿐 총액은 같습니다.

상담 기록은 학기당 수십 건이라 묶지 않았습니다. 낱개로 고치고 지우기가 훨씬 간단합니다.

### 세특은 문서 크기를 재어 봅니다

세특은 이 앱에서 글이 가장 깁니다. 한 건이 1,500바이트쯤이라 한 반에 여러 과목을 모으면
문서가 커집니다(35명 × 12과목 × 1,500바이트 ≈ 630KB). Firestore 문서 한도는 1MiB 입니다.

한도를 넘겨 쓰면 알아듣기 어려운 오류가 나므로, **보내기 전에 크기를 재어 보고**
넘칠 것 같으면 어느 반이 얼마나 큰지 알려 주며 멈춥니다.
한 건도 보내지 않고 화면도 원래대로 되돌리므로, 화면과 서버가 어긋나지 않습니다.

### 화면을 열 때 구독합니다

`profiles` 는 학생이 각자 쓰는 문서라 묶을 수 없습니다(보안 규칙이 문서 단위입니다).
대신 로그인할 때 전부 붙이지 않고, 그 자료가 필요한 화면을 열 때 붙입니다.
각 화면이 무엇을 필요로 하는지 적어 두면 `app.js` 가 처리합니다.

| 화면이 적는 값 | 붙이는 곳 | 예 |
| --- | --- | --- |
| `meta.needs` | `board.js` (공용 컬렉션) | `profiles`, `submissions`, `portfolios` |
| `meta.owns` | `store.js` (선생님 계정 안) | `portfolios`, `achievements` |

학생이 900명이면 `profiles` 만으로도 로그인마다 900건이었는데,
이제 '학생 관리'나 '포트폴리오'를 실제로 열 때만, 그리고 로그인당 한 번만 읽습니다.
선생님이 등록한 포트폴리오도 마찬가지로 포트폴리오·휴지통 화면을 열 때만 읽습니다.

공지·과제처럼 선생님과 학생이 함께 보는 자료는 따로 둡니다.

```
profiles/{uid}      학생이 적은 학년·반·번호·이름
notices/{id}        공지사항   (선생님만 작성, 로그인한 사람은 모두 열람)
assignments/{id}    과제       (선생님만 작성, 로그인한 사람은 모두 열람)
submissions/{id}    과제 제출물 (낸 학생 본인과 선생님만 열람)
portfolios/{id}     포트폴리오  (올린 학생 본인과 선생님만 열람)
```

여기 있는 `portfolios` 는 **학생이 스스로 올린** 자료입니다.
선생님이 등록한 것은 위의 `users/{uid}/portfolios` 로, 이름은 같지만 다른 자료입니다.
세특(`users/{uid}/achievements`)에는 학생이 볼 수 있는 짝이 없습니다.

`firestore.rules` 의 보안 규칙이 이 경계를 지킵니다.

- **상담 기록**은 선생님 본인만 접근합니다.
- **제출물과 포트폴리오**는 낸 학생과 선생님만 볼 수 있고, 다른 학생은 목록에서도 안 보입니다.
- **공지와 과제**는 로그인한 사람이면 모두 읽을 수 있습니다.
  학년·반 지정은 화면에서 걸러 보여주는 것이지 비밀이 아니므로,
  학생에게 보이면 안 되는 내용은 올리지 마세요.

로그인하면 어느 기기·브라우저에서든 같은 데이터를 볼 수 있고,
변경 사항은 열려 있는 모든 창에 실시간으로 반영됩니다.
오프라인일 때는 마지막으로 받은 데이터를 그대로 볼 수 있으며,
다시 연결되면 저장하지 못한 내용이 전송됩니다.

## 처음 준비하기

### 1. Firebase 프로젝트 만들기

1. [Firebase Console](https://console.firebase.google.com/) 에서 프로젝트를 만듭니다.
2. **빌드 → Authentication → 시작하기 → Sign-in method** 에서 **Google** 을 사용 설정합니다.
3. **빌드 → Firestore Database → 데이터베이스 만들기** 로 Firestore 를 만듭니다.
   (프로덕션 모드로 시작한 뒤 아래 4번에서 규칙을 넣습니다.)
4. **Firestore Database → 규칙** 탭에 이 저장소의 `firestore.rules` 내용을 붙여넣고 게시합니다.
   Firebase CLI 를 쓴다면 `firebase deploy --only firestore:rules` 로도 됩니다.
5. **프로젝트 설정 → 내 앱 → 웹 앱 추가(`</>`)** 로 웹 앱을 등록하고,
   화면에 나오는 `firebaseConfig` 값을 복사해 둡니다.

### 2. 승인된 도메인 등록 (중요)

**Authentication → 설정 → 승인된 도메인** 에 앱을 서비스할 주소를 추가해야
Google 로그인이 동작합니다. 없으면 로그인할 때 `unauthorized-domain` 오류가 납니다.

- GitHub Pages 주소: `<사용자명>.github.io` (예: `mayjyeon.github.io`)
- 로컬 개발: `localhost` (기본으로 등록되어 있습니다)

### 3. GitHub Secrets 등록

저장소의 **Settings → Secrets and variables → Actions → New repository secret** 에서
1번에서 복사한 값을 등록합니다.

| Secret 이름 | 필수 | `firebaseConfig` 의 항목 |
| --- | --- | --- |
| `FIREBASE_API_KEY` | ✅ | `apiKey` |
| `FIREBASE_AUTH_DOMAIN` | ✅ | `authDomain` |
| `FIREBASE_PROJECT_ID` | ✅ | `projectId` |
| `FIREBASE_APP_ID` | ✅ | `appId` |
| `FIREBASE_STORAGE_BUCKET` | | `storageBucket` |
| `FIREBASE_MESSAGING_SENDER_ID` | | `messagingSenderId` |

> Firebase 웹 설정값은 브라우저에 노출되는 공개 값이라 그 자체로는 비밀이 아닙니다.
> 실제 보안은 `firestore.rules` 의 규칙과 승인된 도메인 설정이 담당합니다.
> 다만 프로젝트 정보를 저장소에 남기지 않으려고 Secrets 로 주입합니다.

### 4. GitHub Pages 켜기

저장소의 **Settings → Pages → Build and deployment → Source** 를
**GitHub Actions** 로 지정합니다.

이후 `main` 브랜치에 푸시하면 `.github/workflows/deploy.yml` 이
설정 파일을 만들고 GitHub Pages 로 배포합니다.
**Actions** 탭에서 `Deploy to GitHub Pages` 워크플로를 직접 실행할 수도 있습니다.

## 로컬에서 실행하기

빌드 도구나 설치가 필요 없는 정적 웹사이트입니다.
다만 Firebase 설정 파일이 하나 필요합니다.

```bash
# 1) 설정 파일 만들기 (둘 중 하나)
cp assets/js/firebase-config.example.js assets/js/firebase-config.js   # 직접 값 채우기

FIREBASE_API_KEY=... FIREBASE_AUTH_DOMAIN=... \
FIREBASE_PROJECT_ID=... FIREBASE_APP_ID=... \
node scripts/generate-firebase-config.mjs                             # 환경 변수로 생성

# 2) 로컬 서버 실행 (ES 모듈이라 파일을 직접 열면 안 됩니다)
python3 -m http.server 8000
```

브라우저에서 <http://localhost:8000> 으로 접속합니다.
`assets/js/firebase-config.js` 는 `.gitignore` 에 있어 저장소에 올라가지 않습니다.

설정 파일이 없으면 앱이 무엇을 해야 하는지 안내 화면을 띄웁니다.

### 계층

```
views/*  ─ 화면. 데이터 계층을 직접 부르지 않고 아래를 거칩니다.
  │
  ├─ services.js ─ 선생님 자료(학생·상담·포트폴리오·세특)의 업무 규칙
  │      └─ store.js  users/{uid}/… (반 문서 · 상담 기록 · 포트폴리오 · 세특)
  ├─ board.js ──── 공지·과제·제출물·학생이 올린 포트폴리오 (함께 보는 자료)
  └─ trash.js ──── 두 계층에 흩어진 지운 자료를 한 목록으로 모읍니다.
```

## 원본 C# 프로젝트와의 대응

| 원본 (C#) | 이번 웹 버전 |
| --- | --- |
| `CareerCounseling.Core/Entities` | `assets/js/store.js` 의 데이터 구조 |
| `CareerCounseling.Infrastructure` (EF Core + SQLite) | `assets/js/store.js` (Firestore) |
| `CareerCounseling.Wpf/Services` | `assets/js/services.js` |
| `CareerCounseling.Wpf/ViewModels` + `Views` | `assets/js/views/*.js` |
| `CareerCounseling.Wpf/Themes` | `assets/css/style.css` |

유효성 검사 규칙(학년도/학년/반/번호 중복 확인, 필수 입력 항목, 회기 번호 자동 부여)은
원본 로직을 그대로 옮겼습니다.

다만 저장 방식은 다릅니다. 원본은 SQLite 라 학생과 학년도 소속이 별개 테이블이었지만,
여기서는 읽기 건수가 곧 비용이라 한 반을 문서 하나로 묶고 소속을 학생 행에 함께 두었습니다.

## 문제 해결

| 증상 | 확인할 것 |
| --- | --- |
| `Firebase 설정이 필요합니다` 화면 | `firebase-config.js` 가 있는지, GitHub Secrets 가 등록됐는지 |
| 로그인 시 승인된 도메인 오류 | Authentication → 설정 → 승인된 도메인에 배포 주소 추가 |
| `Google 로그인을 사용 설정해주세요` | Authentication → Sign-in method 에서 Google 활성화 |
| 로그인은 되는데 데이터 접근 권한 오류 | `firestore.rules` 를 Firebase 에 게시했는지 확인 |
| 로그인 창이 뜨지 않음 | 브라우저 팝업 차단 해제 |
| 명렬표에서 학생을 못 찾음 | `○반` 제목 줄과 `번호` 열이 있는지, 제목에 `2026학년도 1학년` 이 들어 있는지 |
| 명렬표 업로드가 안 됨 | 예전 `.xls` 라면 엑셀에서 `.xlsx` 로 다시 저장 |
| 내보낸 문서가 안 열림 | 한컴오피스 한글 2010 이상인지 확인 (그 이전 버전은 `.hwpx` 를 지원하지 않습니다) |
| 선생님인데 학생 화면이 뜸 | `roles.js` 의 `TEACHER_EMAIL` 과 로그인한 계정이 같은지 확인 |
| 학생 정보 등록에서 저장 실패 | `firestore.rules` 를 새로 배포했는지 확인 (`profiles` 규칙이 필요합니다) |
| 학생이 공지를 못 봄 | 공지의 공개 대상과 학생이 등록한 학년·반이 맞는지 확인 |
| 첨부 링크를 학생이 못 열음 | 드라이브에서 ‘링크가 있는 모든 사용자’ 로 공유했는지 확인 |
| 지운 자료를 되살리고 싶음 | 휴지통에서 30일 안에는 되살릴 수 있습니다 |
| 통계 건수가 실제보다 많음 | 상담일지 아래 ‘주인 없는 상담 기록’ 카드에서 정리하세요 |
| 포트폴리오 엑셀에서 칸을 못 찾음 | 머리글에 `현재학번` 과 `글내용(통합)` 이 있는지 확인 |
| 포트폴리오가 전부 ‘학생 없음’ | 미리보기의 학년도가 맞는지, 그 학년도 명렬표를 올렸는지 확인 |
| 포트폴리오 저장 권한 오류 | `firestore.rules` 를 새로 배포했는지 확인 (`users/{uid}/portfolios` 허용이 필요합니다) |
| 세특 엑셀에서 칸을 못 찾음 | 머리글에 `학번` 과 `세특 내용` 이 있는지 확인 |
| 세특 저장 권한 오류 | `firestore.rules` 를 새로 배포했는지 확인 (`users/{uid}/achievements` 허용이 필요합니다) |
| 세특이 ‘내용이 너무 많습니다’ 로 막힘 | 한 반에 담긴 양이 한도에 가깝습니다. 나누어 올리거나 오래된 자료를 지워주세요 |
| 내려받은 파일 이름이 `download` 로 나옴 | 운영체제 로캘이 UTF-8 인지 확인 (한글 파일 이름은 UTF-8 환경에서만 그대로 붙습니다) |
